# Tabs close when the Reminder lands, and finished Runs are reopened from a Run Index

Amends [0016](./0016-mirror-pane-displays-never-owns-the-run.md), which decided that "panes linger after their Run ends so their evidence survives" and that they are "reaped when the next Task starts" — the second half of which was never implemented, so panes accumulated for the life of the session. Instead: a **Task**'s **Tab** closes when its **Reminder** is delivered, and any finished **Run** can be **Reopened** from a **Run Index** that spans sessions.

Closing on Reminder delivery rather than on Run completion is the load-bearing detail. The Reminder is the moment the user learns the Task landed and is told how to reopen it, so the Tab survives until that hint is in hand; and since ADR 0027 made Reminders arrive on idle, the Tab never vanishes mid-turn while the user is reading it. The Tab is the unit closed, not the pane, because a Tab holds one Task's Runs — closing panes individually would leave an empty Tab behind, which is clutter of a different shape. The Reminder now carries the reopen command, which is what makes the evidence loss acceptable rather than merely accepted.

The **Run Index** merges two sources because neither is sufficient. The registry is memory-only by design (ADR 0001: tasks die with the orchestrator), so it cannot see past sessions; disk can, but a session file does not record a Task's **Mode**, and `run.json` (ADR 0026) is written best-effort — it is absent from 2 of the 5 run directories currently on disk, including one the user tried to inspect. So the registry wins for the current session, disk fills in the rest, and a row with no `run.json` is listed with its agent shown as `unknown` rather than hidden: the Task ID is the thing being looked up, and the transcript opens with or without a label. Cost is deliberately omitted from the listing because these session files record `cost.total: 0` throughout, and a column that always reads `$0.0000` is worse than no column.

Reopening is addressed by **Task ID**, since that is what the index shows, and opens every Run of that Task. It reuses the existing viewer unchanged: `mirror.ts` already renders any run directory and `openMirrorPane` already thaws an archived session (ADR 0022), so a **Mirror Pane** simply has two lifecycles rather than a new concept needing a new name. An already-open Run is focused rather than opened twice, via the existing `findPaneByLabel`. Both `/run <id>` and a `subagent_tasks` `open` action exist, and both are thin callers of one shared resolver — two surfaces, one implementation, so they cannot drift.

**Considered.** *Closing the pane the instant a Run finishes* is what was asked for, and was refined to Reminder-delivery because a Tab that disappears before the user has been told anything is a worse surprise than one that lingers a moment. *Keeping failures open while closing successes* hedges the evidence loss and was declined in favour of the reopen path covering both uniformly. *Reaping on next Task start* is ADR 0016's original intent and leaves panes from the last Task sitting until new work begins. *A disk-only index* needs no merge and no precedence rule, but loses Mode and reports zero cost for current-session Tasks whose exact values are in memory. *Mining past orchestrator session files* for persisted `details` payloads would recover Mode and state for old Tasks too — the richest option, and much the largest, so it is left as the obvious extension. *A separate Replay Pane concept* keeps the glossary's "live" definition of Mirror Pane intact, and was rejected as a second name for one implementation doing one job.

**Consequences.** Evidence no longer survives on screen: when a Run fails, its pane is gone by the time the user reads the Reminder, and the failure detail lives in the **Result** plus the reopened transcript. That is a real regression against 0016's reasoning, accepted because the transcript is now reachable by ID instead of only by having left a pane open. The extension must retain each Task's `tabId`, which it currently discards after `createTab`. The Run Index is bounded by the reaper: archived after 1 day, hard-deleted after 90, so "all completed tasks" means "the last 90 days". Two listing surfaces now exist — the tool's `list` for when the orchestrator needs the rows in context, and `/runs` for when the user does not want to spend a turn — and both must keep showing the same thing. Because Task IDs are only unique within a process lifetime, a sufficiently old index could in principle show two different Tasks with the same ID; the timestamp in each row is what disambiguates them.
