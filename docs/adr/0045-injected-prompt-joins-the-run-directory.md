# The Run directory records the Injected prompt

The assembled **Injected prompt** — the subagent's system prompt, any preloaded skills, and on the Fallback path the conditional result contract — previously lived only in a temp file deleted in the attempt's `finally`, after the Run had ended, and the Transcript does not record it. Neither the orchestrator nor the user could inspect what a Run was started with, and the in-memory registry dies with the session (ADR 0001), so a keep-the-temp-file design could never serve historical Runs.

**Decision:** record the Injected prompt in the Run directory as `prompt.md` at spawn — a third file beside the Transcript and the Run Meta — and pass that same file across `--append-system-prompt`, so the file on disk is byte-for-byte what the child was started with and the temp file is gone entirely. It is left unarchived like the Run Meta: archiving (ADR 0022) compresses only the session JSONL, and the prompt is small evidence, not history. A new `subagent_tasks` action `prompt` reads it back for a Task's runs, labeled per run (its agent, and its step in a `chain`), because a prompt is read back against the run it started: in a `chain` the prompts are in fact identical — the previous run's **Result** is carried by the *task* prompt, not the Injected prompt — and the label is what identifies the run that has no `prompt.md`, the one refused before spawn.

**Considered options.**

- *Capture the child's final system prompt* (pi's base plus the injected content). Requires a local pi patch (ADR 0034) that dumps the assembled prompt at startup, and couples this repo to pi's internal prompt format, which changes across releases. Rejected: the injected content is what this repo controls and what a reader of the Run would ask to see.
- *Keep the temp file, copy on demand.* The temp file is deleted in the attempt's `finally`, once the Run has ended, and in-memory state does not survive the session, so this answers only "show me while it is running" — and a half-deleted temp dir is a failure mode the Run directory does not have.

**Consequences.** A third file type enters the shared Run directory contract (ADR 0039); consumers scanning a Run directory must tolerate it. The prompt is recorded for delegated `sub-` Runs only — plan-spawned `pln-` Runs (autonomous reviews, rework) still route their prompt through a temp file, so their Run directories carry no `prompt.md`. Runs from before this ADR have no `prompt.md`, and readers report "no prompt recorded" rather than an error. The two spawn paths record exactly what each sends, which makes the Fallback path's result-contract line visible in its `prompt.md` and absent from every Native one — a real difference between the paths, now inspectable instead of assumed.
