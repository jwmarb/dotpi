# Mirror Panes are append-only so the terminal owns the scrollback

A **Mirror Pane** now prints only what is new since its last draw and never clears the screen. Previously it redrew a full frame every tick: `ESC[H ESC[2J ESC[3J`, then the header plus only as much of the body as fit the window. That made the pane unscrollable in two independent ways, and both had to be fixed. The body was *truncated* — `body.slice(body.length - room)` discarded every line above the visible tail, so the overflow was never written anywhere. And `3J` *deletes the terminal's scrollback buffer*, so even the lines that had been displayed were destroyed on the next poll, once per second.

Nothing pinned survives in an append-only stream, so the four-line boxed header is gone. In its place a one-line status — agent, task, model, turns, cost, state — is emitted only when it changes. That reads as a natural progress log (`0 turns → 1 turn → 2 turns  stop`) and costs one line per change rather than one frame per tick. The pane never entered the alternate screen, so dropping the clears is all it takes for the terminal's native wheel and scrollback to work.

The **Board** keeps its full-frame redraw but loses `3J` alone. A Board is a fixed-size projection of a **Plan**, not a growing log, so redrawing in place is right for it; destroying the pane's scrollback as a side effect never was.

> **Corrected by [0031](./0031-board-uses-alternate-screen-and-pages.md).** The claim that a Board is "fixed-size" was false: a 23-item plan renders ~141 lines, taller than any pane. Dropping `3J` while still drawing on the normal screen therefore left every scrolled-off frame stacked behind the next one. The Board now draws on the alternate screen and pages its own frame.

**Considered.** *An internal scroll viewport* with keybindings and a scroll offset keeps the pinned header and full-frame redraw, and was rejected because it means raw-mode key handling, an auto-follow-versus-frozen mode, and competing with the terminal's own wheel for the same gesture. *An alternate-screen pager* (`?1049h`, like `less`) is the most controlled option and the most machinery, and it makes native scrollback unavailable by construction — the opposite of what was asked for. *Simply raising the truncation limit* would move the cliff without removing it. *Keeping the header by reprinting it per frame* is incompatible with append-only output: it would litter the scrollback with a header per tick.

**Consequences.** Three behaviours follow from the terminal owning the history rather than this process. Resize no longer reflows: previously printed lines keep their original wrapping, because reprinting them to reflow would duplicate history the pane no longer owns — so the resize handler is gone. A shrinking session file (a **Thaw** replacing the file, or a fresh **Run** in the same directory) is treated as a new stream and reprinted from zero, since the alternative is silently emitting nothing. And the cursor is no longer hidden, because hiding it only made sense while this process owned the whole frame. The footer note that closing a pane does not stop the **Run** is also gone — it cannot live at the bottom of an append-only stream, and that guarantee is documented in `CONTEXT.md` instead. Finally, because output is now incremental, the renderer's line count is load-bearing state: any change that makes `renderTranscript` emit a *different* prefix for the same entries would duplicate or skip content, where before it would merely have redrawn.
