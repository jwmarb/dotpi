# The Board writes the plan file directly, superseding ADR 0013's single-writer rule

Supersedes [0013](./0013-plan-mutation-goes-through-one-tool.md) in part: the `plan` tool is no longer the *only* writer of a plan file. The **Board** — a live kanban process in its own **Pane** — writes `plans/*.jsonl` directly, so that moving a card is instantaneous and works whether or not the orchestrator is mid-turn. Both writers take a lockfile and write temp-and-rename; the Board revalidates the schema on every write, and honours the self-archive rule identically. The `plan` tool re-reads the file before every mutation and reports any change it did not make, so a card the user moved is never clobbered by the orchestrator's next op.

**Considered.** *Board proposes, tool disposes* — the Board sends a prompt to the orchestrator's pane and lets the tool commit — preserves 0013 completely and was the recommendation, but it makes every card move depend on a live orchestrator and cost a turn, so the board lags the user's hand. *A socket into the plan extension* keeps one writer in code with two front doors, at the price of growing a server inside the extension and still dying with the session. *Read-only board* was the cheapest and was rejected as not being the thing that was asked for.

**Consequences.** The invariants 0013 centralised are now duplicated: schema validation, atomic replacement, and the archive-on-all-terminal rule exist in two codebases and can drift. That duplication is the real cost of this decision and any change to the plan file format must now be made twice. The lockfile is a new failure mode — a crashed holder must not wedge the plan, so the lock has to be stale-breakable. ADR 0011's dual-sourcing survives, but the conversation copy is now provably stale between plan ops: the orchestrator can reason about an item the user already moved until it next touches the tool.
