# The Board reads Run sessions to show Task progress, via a `run.json` sidecar

A **Board** card whose **Plan Item** carries a **Task ID** shows that Task's live progress — `explorer · 4 turns`, with a trailing ellipsis while it is still working — instead of the bare `[sub-6748]` it showed before. A Task ID alone tells the user nothing about whether anything is happening.

This makes the Board a reader of **Run** session files, which it was not. Two facts forced a sidecar: a session file records what the child *did* but never which specialist it was, and the Board is a separate process with no view of the Task's in-memory state. So each Run now writes `run.json` (`runId`, `agent`, `step`) beside its session, and the Board maps a Task ID to its Run directories by prefix (`sub-6748` → `sub-6748-1`, `-2`, …), summing turns across them. A Task is reported finished only when *every* Run is: a parallel Task with one Run still working is still working.

The Board's poll loop also changed meaning. It previously redrew only when the plan file's mtime moved, but a Run writes its own session and never touches the plan — so turn counts would have sat frozen for the entire life of a subagent. While any Task is unfinished the Board now redraws on every 2s tick regardless of the plan's mtime.

**Considered.** *Showing only a marker that a Task is attached*, from the `taskId` the plan already holds, needs no new I/O and no sidecar; it was rejected as barely more informative than the Task ID already on the card. *Full status — turns, cost, and lifecycle state* was declined for now as more surface than the question warrants. *Having the subagent extension write progress into the plan file* would keep the Board single-file, and was rejected because it makes every subagent turn a plan-file write, contending on the lock (ADR 0015) with the orchestrator and the Board for data that is not part of the plan. *Deriving the agent name from the session file* avoids the sidecar entirely, but the name simply is not in there.

**Consequences.** The Board is no longer a single-file reader, which is a real widening of a process deliberately kept dependency-free: it now reads `plans/*.jsonl` plus every referenced Run's directory, and it infers the agent directory by walking up from the plan file's path. Runs that predate the sidecar degrade to the literal label `subagent` with a correct turn count, so nothing breaks retroactively. Progress is recomputed from scratch on every redraw by re-reading whole session files; that is fine at current sizes and is the obvious thing to make incremental if a long run makes it hurt. Reaping (ADR 0022) will eventually archive a Run whose Plan Item still names it, at which point the card falls back to `waiting to start` — a stale label for finished work, and the reason a future change should prefer the archived Run over nothing.
