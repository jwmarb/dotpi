# The Board runs on the alternate screen and pages its own frame

The **Board** enters the alternate screen (`?1049h`) on start, restores the normal screen on every exit path, and keeps a scroll offset so a frame taller than the pane can be paged with `↑`/`↓`, `PgUp`/`PgDn`, `g`/`G`. This replaces the arrangement from ADR 0029, where the Board redrew full frames on the normal screen with `ESC[H ESC[2J` and no `3J`.

That arrangement was broken, and the reasoning behind it was wrong. ADR 0029 justified dropping `3J` by calling the Board "a fixed-size projection, not a growing log" — but a 23-item plan renders a **141-line frame**, which overflows any pane. Printing it scrolls the terminal buffer; `2J` clears only the visible region; and `3J`, the thing that had been discarding the scrolled-off remains, was gone. So every redraw stacked another copy of the Board behind the last one, overlapping. The alternate screen removes the whole class of problem rather than trading one side effect for another: it is a separate buffer, so no frame can scroll the pane's real history and no clear can destroy it.

Paging follows from that choice rather than being an independent feature. On the alternate screen the terminal's own wheel and scrollback do not apply, so if the frame does not fit, the Board must move it itself. Raw mode is required to receive individual keypresses, which means `ctrl+c` no longer arrives as a signal and is handled explicitly in the key handler.

**Considered.** *Restoring `3J`* is a one-token revert that fixes the corruption and reinstates exactly the side effect it was removed for — wiping the pane's scrollback every two seconds. *Clipping each frame to the pane height* keeps the real scrollback intact and stops the stacking, and was rejected because it makes most of a long plan permanently unreachable — the same truncation fault removed from the **Mirror Pane** in ADR 0029. *Making the Board append-only*, as the Mirror Pane now is, sidesteps escape sequences entirely and would print 141 fresh lines every two seconds. *Rendering more compactly* (collapsing accepted items, hiding notes) reduces the overflow without addressing it and remains available as a complement.

**Consequences.** The Board and the **Mirror Pane** now sit on opposite sides of the same trade, deliberately: the mirror is append-only so the terminal owns its history and the wheel works, while the Board is a full-frame pager whose history is its own and whose movement is keys-only. Anyone unifying them later must re-derive that a log and a dashboard want different things. The alternate screen introduces a new failure mode — a crash or a missed exit path leaves the pane on a blank buffer with a hidden cursor, looking dead — so `SIGINT`, `SIGTERM`, `SIGHUP`, `exit`, and `uncaughtException` all restore the screen. Raw mode means the Board now consumes keystrokes in its pane, where before it ignored input entirely. Scroll position is preserved across redraws and clamped when the frame shrinks, so a plan that gets shorter cannot leave the view stranded past the end.
