# Run sessions are archived by compression, and thawed on open

Run session files (docs/adr/0019) are no longer ephemeral and nothing deleted them, so `~/.pi/agent/subagent-sessions/` grew without bound — a single oracle consultation measured 296 KB. A Run's session now has three states: **live** (plain JSONL, readable by herdr's sidebar and the Mirror Pane) → **archived** (zstd, cold storage) → **gone**. Compression *is* archiving. A Mirror Pane asked to display an archived Run thaws it back to plain JSONL first (`thawRun`), so opening a Run is what makes it readable again.

Defaults: archive after 1 day, delete after 90 days, and never touch anything written in the last 5 minutes. Reaping runs detached at session start, in TUI mode only.

**Measured, not guessed.** On the real 302 KB session, using node's built-in `zlib` so no dependency is added: zstd 4.0x in ~1 ms, brotli 5.1x in 248 ms, gzip 3.6x in 8 ms. zstd was chosen because 1 ms is cheap enough to run eagerly at every session start while remaining shell-readable via `zstd -d`. End to end on the real directory: 304 K → 84 K (225 KB saved), then thawed back losslessly (400/400 lines on the synthetic case).

**Considered.** *Deletion-only retention* was the original plan and was rejected in favour of compression: nothing is lost, and a Run's reasoning stays recoverable. *Compression with no deletion at all* was rejected because it only slows unbounded growth rather than bounding it — hence the distant 90-day backstop. *Reaping a session when its Mirror Pane is reaped* would match the pane lifecycle but destroys exactly the durable evidence 0019 created. *Teaching the Mirror Pane to read compressed sessions transparently* was rejected in favour of thaw-on-open: one readable format at a time is simpler than two readers, and it keeps herdr's sidebar and the viewer agreeing about what a session file is.

**Consequences.** An archived Run is invisible to herdr's sidebar until something thaws it — compressed sessions are genuinely cold, and that is the accepted cost of the simpler contract. A Run is never both live and archived for longer than one write, and if a thaw or archive is interrupted the *plain* file always wins, so an interruption cannot lose a transcript. The reaper is deliberately conservative twice over: it skips runIds this process has in flight, and independently skips anything recently written, because another pi process may own a Run this one knows nothing about.
