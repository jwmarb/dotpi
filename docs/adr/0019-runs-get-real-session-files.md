# Runs get real session files so herdr can show them

Runs were spawned `--no-session` (deliberately ephemeral: the **Result** is the product and the **Transcript** is discarded). They now get a real session file via `--session-id`, because herdr's agents sidebar shows a *browsable live session* keyed off a session path, and a `--no-session` child has nothing to show. The **Mirror Pane** additionally calls `herdr pane report-agent` to declare itself — name, lifecycle state, and `--agent-session-path` — the same mechanism `herdr-agent-state.ts` uses to advertise the root pi. A **Run** therefore appears in `herdr agent list` as a first-class agent without herdr having to detect one.

**Considered.** *Keeping `--no-session`* preserves ephemerality and still permits a live-output pane, but the sidebar entry would have no session to open — a terminal view, not the browsable session that was asked for. *Opt-in per delegation* keeps most runs ephemeral, and was rejected because the sidebar becomes inconsistent: you cannot tell which subagents are inspectable until after they run. *Letting herdr own the run* (`agent start --kind pi`) yields native lifecycle detection for free and was rejected again for the reason in [0016](./0016-mirror-pane-displays-never-owns-the-run.md) — the Result would have to be scraped from a terminal.

**Consequences.** Runs are no longer ephemeral, so session files accumulate and need deliberate reaping; this is new janitorial work that did not exist before, and an unreaped subagent session dir will grow without bound. `CONTEXT.md`'s claim that the orchestrator "reads Results, not Transcripts" is unchanged for the orchestrator, but the Transcript is now durable and user-visible — a Run's reasoning outlives the Run. Self-reporting means herdr's `blocked` for a Mirror Pane is *declared by us*, not detected from the screen, which is why it can be trusted for a JSON-mode child that has no recognisable UI on screen.
