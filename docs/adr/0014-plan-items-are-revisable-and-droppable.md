# Plan Items are revisable in place and can be dropped without being failed

The `plan` tool could only append items and move them between `pending`/`active`/`done`/`failed`, so an agent told mid-session to change course — typically by an `oracle` or `planner` **Result** — had no way to reword a **Plan Item** and no terminal state meaning "we changed our mind." It marked the step `failed` with an explanatory note instead, which is a lie about what happened. We add a `revise` op that rewrites an item's `text`, and a third terminal state `dropped` for abandoned steps.

**Considered.** Letting `seed` clobber a live plan behind a force flag would make a full re-plan one call, but it silently destroys the `taskId` links that tie **Plan Items** to in-flight **Tasks**; `revise` keeps ids, order, notes, and task linkage stable. A `remove` op that deletes the line was rejected for the same reason `seed` refuses non-empty files: losing the fact that a step was ever planned is worse than a visibly-abandoned entry. Continuing to overload `failed` was rejected because the archived record is the only history the format keeps (see ADR 0011) and it should not conflate "we tried and it broke" with "we decided not to."

**Consequences.** `revise` writes `text` only — `note` is already writable through `status`, and `taskId` stays write-once so an item cannot be silently repointed at a different **Task**. It refuses items in a terminal state: rewriting what a landed step claims to have done rewrites the record, and the plan may already be archived. `dropped` is terminal, so self-archiving still fires when the last open item lands, but it is excluded from the progress denominator (`Plan 3/4 (∰1)`) — abandoned work is not work you owe. Because `loadPlan` treats an unrecognised `status` as a corrupt line and skips it, adding a state would make `dropped` items vanish when read by an older build; `loadPlan` therefore now preserves unknown states as `pending`, trading a small lie about state for never losing a step. ADR 0011's "file is state, not history" still holds: a revision overwrites, leaving no trace of the prior wording.
