# The Board mirrors the route field by hand, and displays it before it can write it

> **Status: implemented.** `board.ts` hand-mirrors `route` and renders a
> per-card glyph in every column: `◇` for `oracle`, `⇢` for `skip`, and nothing
> for `user` — the default needs no mark, and marking it would add noise to every
> card to say "nothing unusual". An unrecognised route is dropped rather than
> rendered as though understood. The writer remains a stub, as below.

The **Board** renders each Item's **Review Route** as a per-card glyph in every column, not only in `review`, so a `skip` is visible while the Item is still being groomed — early enough for the user to object before the work is done. Because the Board process is deliberately dependency-free and cannot import the plan extension, the new `route` field is hand-copied into its local `PlanItem` mirror exactly as `PlanState` and the column list already are.

**Considered.** *Extracting a shared schema module* both processes import would kill this whole class of drift, and was rejected as a refactor of a deliberately standalone process, out of scope for this change. *Rendering the route as an opaque passthrough string* — the Board displays whatever it finds and validates nothing — is attractive because the Board needs no opinion about what a route *means*, only how to draw it; it was rejected as inconsistent with how the Board already canonicalises state. *Showing the glyph only in the `review` column* would tell the user which Items wait on them versus on oracle, but makes a `skip` invisible by construction, which defeats the "self-certifies, but visibly" requirement that motivated the display.

**Consequences.** This is the third hand-copied structure between the two files, and ADR 0015 already named that duplication as its real cost — the count is now high enough that the shared-module refactor is a matter of when, not whether. A route the Board does not recognise must degrade visibly rather than silently, since the Board's existing habit is to misfile unknown values into `backlog`; a route it cannot parse should read as "unknown route", never as `skip`. Note the ordering oddity this creates: the Board gains a *display* of the field while it still has no writer at all (ADR 0015 granted it write rights, but the writer remains a stub), so route changes are read-only on the Board and must be made through the `plan` tool's `route` op. Card movement, when the Board's writer does arrive, will have to enforce the ratchet independently — a user dragging a card must not be able to lower a route the way an agent cannot.
