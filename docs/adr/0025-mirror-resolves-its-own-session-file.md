# The Mirror Pane resolves its own session file from the Run's directory

A **Mirror Pane** is given its **Run**'s session *directory* and finds the newest `.jsonl` in it, latching on once one appears. Previously the parent resolved the filename up front, waiting up to 15s (60 × 250ms) for the child to create it and otherwise falling back to `pending.jsonl` — a path nothing ever creates. That fallback is deleted along with the wait.

This was a live bug, not a theoretical one. A child took 15.78s to write its first line (extension load and MCP connect precede the first session write), the 15.0s budget expired 0.78s early, and the pane spent the whole run watching a nonexistent file: permanently `0 turns`, no live updates, and no visible prompt. The prompt in particular was never a missing feature — the renderer already emits a `▶ task` block from the session's user message, and it rendered correctly the moment it was pointed at the real file.

**Considered.** *Raising the timeout* is a one-character fix and was rejected because it only moves the cliff: a slower machine or a larger MCP set loses the same race, and the failure mode is silent. *Passing the directory but keeping the filename as a hint* was rejected as leaving the fallback path alive as a dead concept for no benefit. *Having the parent watch and tell the viewer later* keeps resolution in one place, but adds a message channel between two processes that already share a filesystem.

**Consequences.** The viewer now owns discovery, so the parent no longer blocks on a deadline it cannot honour and a late-starting child is a non-event. The `findSessionFile` helper in the subagent extension became dead and was removed; the parent still calls `thawRun` before opening, so an archived Run (ADR 0022) is still restored first. Because the filename is not known when the pane opens, the directory watcher can no longer filter events by basename and every event in the Run's directory is a redraw candidate — cheap, since the directory holds one session and one `run.json`. The name is latched on first resolution rather than re-globbed, so a thaw or reap racing a redraw cannot make a pane jump to a different Run's transcript. An empty directory now renders `waiting for the run to start…`, which is honest, where the old path rendered a confident and permanent `0 turns`.
