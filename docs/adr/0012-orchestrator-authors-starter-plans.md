# The orchestrator authors each subagent's Starter Plan and never reads it back

> **Superseded in part by [0048](./0048-every-run-carries-its-own-plan.md).** The crossing channel below — the Starter Plan carried *as text in the delegation prompt* and then seeded into the child's plan file after delegating — is replaced: the items now cross into the child's plan file at spawn, and never inside the **Delegation brief**. The ownership decision stands: the orchestrator authors the plan, the child owns it from spawn, and the orchestrator never reads it back.

Subagents run models that are not as strong as the orchestrator's, so the SOTA orchestrator's guidance is the highest-leverage thing it can hand down: before delegating, it writes the child's **Starter Plan** — as the child's plan file (keyed by the **Task ID**, with a run ordinal for multi-run Tasks), seeded at spawn and no longer carried as text in the delegation prompt (that channel is the one ADR 0048 supersedes; see above). From that moment the child owns the plan: it maintains its own file, and the orchestrator never reads it back.

**Considered.** Summarizing the child's plan into its **Write-up** was rejected: it breaks the **Result**/**Transcript** boundary the delegation ADRs drew — the orchestrator consumes results, not the child's internals. Context-only child plans (no file) were rejected because the discipline would be uneven across agent kinds and children would lose their plan to compaction on long runs. Children authoring their own starter plans was rejected outright: that is the guidance we are trying to give them.

**Consequences.** The subagent spawn must pass the plan key to the child process (an env var, since `--no-session` children have no durable session id of their own to key on). Plan files of children live alongside the orchestrator's own plan files — the folder is a mixed population, and anything that assumes "one plan file = the main session's plan" must key explicitly.
