# A Mirror Pane claims herdr's official pi identity to get a browsable session

A **Mirror Pane** launches its viewer with `HERDR_AGENT=pi` and reports its session using herdr's official `herdr:pi` / `pi` source-agent pair. Both are required, and neither is obvious:

1. **Detection.** Herdr only attaches a session to a pane where it *detected* an agent process. Our pane runs a Bun viewer, so nothing is detected and the session is refused. `HERDR_AGENT=pi` is herdr's documented hint for a foreground wrapper that hides the real agent, and it makes detection fire.
2. **Authority.** Herdr keeps a whitelist of "official" source/agent pairs and **silently discards** a session reported under any other pair. A custom source such as `pi:subagent` yields an agent-list entry with `agent_session: null` and no error. For pi the accepted pair is exactly `("herdr:pi", "pi")`.

Consequently the agent label must stay canonical `pi`. Specialist identity (explorer, oracle, ...) is **presentation**: it lives in the pane label and the report message, never in the agent label.

**Measured.** With an identical session path and label, `report-agent` attached on a pane running pi and returned `agent_session: null` on a shell pane. `agent explain` named the cause: *"does not have a detected agent label."* After adding `HERDR_AGENT=pi`, `agent explain` reported `agent: pi`, and the session attached as `kind: path` with the exact Run session file. The viewer kept rendering appended records live (1 turn → 2 turns), and the root pi pane's own session was unaffected.

**Considered.** *Accepting a pane-only view* remains the safest option and loses only herdr's native session browser — it stays the fallback if this shim ever breaks. *Letting herdr own the run* (`agent start --kind pi`) gives real detection for free and was rejected again for [0016](./0016-mirror-pane-displays-never-owns-the-run.md)'s reason: Results would come from terminal scraping. *A second pi resuming the Run's session file* was rejected after testing — a resuming process **appends to the same file** (a probe added a second turn to a finished session), so a spectator would corrupt the Run's transcript; `--fork` is non-destructive but then shows a copy, not the live Run. *`--mode rpc` in the pane* fails because pi's own herdr integration ignores non-TUI modes.

**Consequences.** We claim a source namespace herdr reserves for its own integration. This is a compatibility shim, not a documented extension point, so **a herdr upgrade may tighten source ownership or process validation and break it** — it must be re-tested after upgrades, and the pane-only view is the designed fallback. The viewer deliberately tells herdr it is a pi wrapper, which is semantically defensible (it is a pi session viewer) but is not a pi process. The installed `herdr-agent-state.ts` must never compete for the same pane; it does not today, because the viewer loads no pi extensions. `releaseAgent` requires the agent label to match the claim, so releases must pass the same canonical label.
