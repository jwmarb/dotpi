# subagent-herdr — herdr-backed subagent delegation

Owns the `subagent` / `subagent_tasks` tools (advertised by the orchestrator prompt). Each delegation is a new herdr tab in the orchestrator's workspace running a native `pi` TUI, plus a run directory under `agent/subagent-runs/`.

**Delegation is event-driven: there is deliberately no blocking wait.** The orchestrator delegates, ends its turn, and is woken by a *notice* the child types into its pane (`herdr agent prompt`) when the child reports or finishes. A blocking wait is what the module used to do, and it made mid-run messaging structurally impossible: the wait ran inside a tool call, so the parent was streaming, so a child's report could only queue as a follow-up and stayed invisible until the child was already dead. Do not reintroduce one.

**The briefing is delivered as `deliverAs: "steer"`, and that word is load-bearing.** pi's agent loop drains its two queues from different places (`pi-agent-core/dist/agent-loop.js`): steering at the end of *every* turn inside `while (hasMoreToolCalls || pendingMessages.length > 0)`, follow-ups only *after* that inner loop exits. So a follow-up reaches an orchestrator that is still calling tools only once it has stopped calling them — i.e. once its turn is already over. Delegating and then continuing to work (a read, a grep, another spawn) kept the loop inside the inner `while`, where the follow-up queue is never polled, so a finished child was unreachable for the rest of the turn however long it lasted. Steering cuts in at the next turn boundary, after the current tool results are in context and before the next LLM call, so it never splits a `tool_call`/`tool_result` pair. Interrupting is the intent: a subagent's answer is new information that should redirect the loop, not queue behind the work it invalidates. The idle path is untouched — `deliverAs` is only consulted while `isStreaming`.

The queue structure and `deliverAs` were last re-verified against an installed pi in the 1.0.x
line; `index.ts`'s comment still cites the original 0.99.2 measurement, and the running pi is
now **1.0.4**. Two revisions of this paragraph disagreed about which 1.0.x it was, so re-measure
against the installed bundle rather than trusting any version written here.

## CONVENTIONS (local)

- **The contract is spelled once.** The child is launched with `-e` and imports only shared modules (`rundir.ts`, and `../lib/agents.ts` for agent definitions) — run-dir paths and JSON shapes change there, never in both halves.
- **Pane and tab ids come from herdr responses, never predicted.** The *agent name* and the run id are the opposite: constructed locally (`herdrAgentName` = `<agent>-<runId>`, `makeRunId`), with herdr's `agent_name_taken` the collision detector.
- **`herdr.ts` never throws.** Every entry point resolves a structured value; the delegation surface must not take down the session hosting it.
- **Pinned to herdr 0.9.0.** Re-verify the "measured behaviours" in `herdr.ts`'s header against the version before changing any of them.
- **Completion is two signals:** the `subagent_done` tool (injected into every child's allowlist) or a clean `agent_end`. A failed turn writes no sidecar, so the parent classifies from its absence.
- **Neither completion signal fires without a visible answer, and one predicate decides what that means.** `qualifiesAsAnswer` (in `rundir.ts`, beside the paths and the notice grammar, because it spans the same seam) is applied by the child's gate *and* by the parent's `extractRunResult`: visible assistant text only, and under a `<result>` contract a complete `<result>…</result>` element. **Whether the contract applies is read off the run's own `system-prompt.md`** rather than hardcoded or declared in frontmatter — every agent in `agent/agents/` ends its prompt with "Only what is inside `<result>` reaches the orchestrator", the three `technical-analysis` journal agents do not, and a future one need not. Thinking is never consulted: reasoning does not reach the orchestrator, so a report composed there is not an answer. The gate exists because both signals were taking the model's word for something it got wrong in 9 of the 37 recorded `explorer` runs, plus 5 of the 64 `librarian` ones — the report went into a fabricated `subagent_done` argument (the schema is `Type.Object({})`, and typebox accepts extra properties, so the call was *valid* and the payload discarded), or into thinking, or nowhere, and **both ends recorded a success**. `subagent_done` is refused `MAX_REFUSED_COMPLETIONS` (2) times and then allowed through — a child that can never finish is worse than one that finishes badly — and a silent clean `agent_end` gets exactly one `sendUserMessage` nudge before completing as before. Do not make either bound unbounded, and do not let a refusal write the sidecar: the sidecar is what makes the parent call the run `done`.
- **Parent-side salvage is deliberately looser than the gate, and that asymmetry is load-bearing.** The gate asks "may this run finish?" while the child can still fix it; salvage asks "is there anything worth forwarding?" once the alternative is `(no final answer in transcript)`. So `extractRunResult` falls back to the done call's own string arguments (preferring `message`) and then to an earlier message, judged by `qualifiesAsSalvage` — a complete `<result>`, or any text past `SUBSTANTIAL_ANSWER_CHARS` (400). That bar is set from the real runs: the three stranded reports were 7.5 KB, 9.2 KB and 17.4 KB while the filler lines left in their place were 48, 62 and 63 chars. **Requiring even an opening `<result>` here was tried and measured — it discards two of the three**, which carried no tags at all; a model that spends its budget on a tool argument gets truncated. Salvage proceeds in four steps — strict answer, then done-call arguments, then substantial text, then *any* visible text as `non-conforming` — and each is labelled in the briefing (`truncated-answer`, `earlier-message`, `done-arguments`, `non-conforming`) so a recovered or inadequate report is never mistaken for a clean one. **The four steps and their inclusive bounds are a regression gate, not a preference:** an earlier draft keyed the search on the last *entry* and started the looser pass *below* it, which lost 47,678 chars across 20 of the 164 recorded runs (8-15 KB reports in `sub-c62b`/`sub-1a09`/`sub-db10`, and a 15,430-char answer replaced by a 565-char interim note in `sub-7864`) while all 190 tests passed — because every fixture happened to have a `subagent_done` call and the dominant real shape has none. Re-run the full replay over `agent/subagent-runs/` after touching this function; the invariant is **zero** answers lost or shortened against the previous implementation.
- **The notice grammar lives in `rundir.ts` and is parsed strictly.** The parent *swallows* every input that matches it, so a loose pattern would eat a human's typing. Both ids are constrained (`sub-` + four hex; herdr's agent-name rule), and anything that does not match is passed through untouched.
- **A child's prompt is its definition body plus whatever `skills:` names.** pi builds `## Available Skills` for the orchestrator only, so without that key a subagent cannot know any skill exists. An agent that declares no skills gets a byte-identical prompt, which is what makes the feature safe to leave off. Discovery failing costs the catalogue, never the launch.
- **`skills:` resolves against pi's own catalogue, not just `agent/skills/`.** The `before_agent_start` hook captures `systemPromptOptions.skills` into `piSkillCatalogue` and `skillEntriesFromPi` maps it; `spawnRun` prefers that over scanning the skills dir. That is what lets an agent declare a skill from an installed package (`test-driven-development`) or a project-local `.pi/skills` at all — `selectSkills` drops unknown names by design, so before this such a declaration resolved to *nothing* with no error, and the agent merely looked like it was ignoring its skill. Taking pi's already-resolved list also means the human's resource filters (`-skills/foo`, include-lists, `autoload: false`) are honoured for free: a child can never be handed a skill the orchestrator was denied. **Do not re-read `settings.json` to rediscover this** — that is a second parser of a format pi owns, and the first draft of this feature had already drifted from pi on pinned `git:…@ref` sources and on per-skill excludes. Keyed on the *directory*, since `selectSkills` matches `dir` and frontmatter `name` may differ. `disable-model-invocation` skills are retained: pi strips those only when rendering the orchestrator prompt, and an agent that names one should get it. Scanning `agent/skills/` remains the fallback for a spawn before any turn has started.
- **`fallback_models` has two jobs, and both read the same list.** `candidateModels` walks it to get the child **launched** — one attempt per model, where an attempt spans opening a pane *and* getting the task accepted (a dead model does not fail the launch, so prompt rejection is the first reliable signal). `childFallbackChain` hands the same list to the *running* child as `PI_FALLBACK_CHAIN`, and the child launches on `fallback/auto` instead of one model so a provider error mid-task hops to the next entry rather than re-asking the one that just failed. The two must agree on which models are in play — a child launched on a model its router cannot route to would be a silent downgrade — which is what the `agrees with candidateModels` test pins. Both return nothing when the delegation call named a `model`: the caller pinned it. The env var's name and the router's id are imported from `../model-fallback/lib.js`, never restated here. A child with no chain launches byte-identically to pre-feature, which is what makes the addition safe for an agent that declares no fallbacks.
- **Ancestry is accumulated by processes, not trusted from models.** `buildChildEnv` stamps `PI_SUBAGENT_LINEAGE` (the agent-name chain, oldest first) into the child; `lineageRejection` reads it back one process later and refuses *before* a run dir, registry entry or pane exists. Two rules, cycle first: an agent in its own ancestry is refused (so `librarian → librarian` cannot happen), then `callable_by` is honoured (so `summarizer` is the librarian's alone). An empty lineage is the human's orchestrator and may spawn anything. This replaced a numeric `MAX_DEPTH`, which had to be tuned and whose obvious value of 1 refused the orchestrator's own child; ancestry needs no constant because the roster is finite. `../lib/dotenv.ts` records the fork bomb this interlock exists to prevent.
- **A `done` notice is only a prompt to look, never the evidence.** The `.exit` sidecar on disk is what classifies a run; a notice that never lands costs promptness, not correctness — which is why every read path calls `reconcile` first.
- **A flush sweeps the registry, so a fan-out that finishes together produces one response.** `flushNotices` calls `collectFinished` before composing: it reconciles every running run (concurrency 8) and folds any that have already finished into the same briefing. The `briefedFinishedRunIds` set suppresses a later notice for an already-briefed completion, and `flushChain` serializes flush bodies so overlapping timers cannot race the dedup set. `steeringMode: "all"` in `agent/settings.json` is the backstop: if two briefings ever land in the steering queue simultaneously, pi drains both into the same next turn.
- **The child's notice is `spawn`ed detached.** `closeOwnPane()` kills the child's process group moments later, and a delivery still attached would die with it.
- **herdr agent names are unique among *live* agents server-wide (a name frees when its agent exits or is released), so children register as `<agent>-<runId>`** (`herdrAgentName`). The bare definition name let the first live `librarian` own it and made every concurrent sibling unlaunchable with `agent_name_taken`. The *bare* name still goes in the notice grammar and `PI_SUBAGENT_AGENT` — only the herdr registration is scoped. herdr's 32-char ceiling applies to the **scoped** name, which leaves a definition name 23.
- **Validate the *scoped* name, never the definition name** (`childNameRejection`). Scoping costs 9 chars, so a 24-char definition name is legal alone and illegal once scoped — checking the bare string let that fail late, after a pane was opened.
- **A herdr refusal arrives on stderr with a non-zero exit**, not on stdout (measured, 0.9.0). `herdr()` parses the `{"error":{"code"}}` document off *either* stream; a catch branch that only reported "herdr exited 1" is what disguised `agent_name_taken` as a launch timeout for five runs. `classifyExecFailure` is pure and tested because the bug was *not looking* on the stream that carries the code.

bun test agent/extensions/subagent-herdr/              # all three suites (lib, child-done, wake) — 201 tests
bun test agent/extensions/subagent-herdr/lib.test.ts   # just the launch/pure-logic suite

`child-done.ts`, `index.ts`, `rundir.ts`; this is the only dir with a `package.json` (the other three typecheck scopes — `model-fallback/`, `ralph-loop/`, and the top-level `agent/extensions` scope — borrow this `tsc`) — dev-only
(`typescript`, `@types/node`); pi loads `index.ts` directly and needs none of it at
runtime. Run it from here with the local binary:

```sh
./node_modules/.bin/tsc -p tsconfig.json
```

This is the **one typecheck scope whose own `tsconfig.json` has no `paths` entry**, so its
`@earendil-works/*` types come from the stale `~/node_modules` (0.75.4) rather than the running
pi — and, because bun honours `paths` at runtime too, so does anything `bun` runs *that lives
in this directory* (resolution keys off the file's location, not your cwd). Note this is an
opt-*out*: `agent/extensions/tsconfig.json` one level up does map `paths` at the live bundle,
and a paths-less tsconfig here shadows it — so sibling dirs with no tsconfig at all
(`trade-journal/`, `auto-update/`) resolve the live bundle while this one does not. It gets

`model-fallback/tsconfig.json`) the moment anything here touches a post-0.75.4 API; the root
AGENTS.md COMMANDS section has the per-scope table.

## ANTI-PATTERNS

- Hand-writing run-dir paths, JSON shapes, or the notice grammar in `index.ts`/`lib.ts` *and* `child-done.ts` — the drift this module was refactored to kill; `rundir.ts` exists because nothing else would have caught it.
- **Adding any form of blocking wait, poll loop, or sleep-until-done to the parent.** It re-breaks mid-run messaging for the reason described at the top of this file. Ending the turn *is* the wait.
- Widening the notice regex to be "more forgiving". It decides what the orchestrator silently eats from its own input stream; a false positive loses a user's message.
- Closing a failed pane "to tidy up" — herdr destroys scrollback when a pane closes, and the scrollback is the failure evidence.
- Treating `agent read` as JSON — it is the one herdr command that prints raw terminal text, not a JSON document.
- Registering a child under its bare agent name, or otherwise making a herdr identity that two live children could both want. Names are as unique-by-construction as pane ids.
- Flattening a herdr error code into a generic message before the fallback loop sees it. `agent_name_taken` and `invalid_agent_name` are `fatal` — retrying them across three models turns one actionable code into a fake fleet outage.
- **Switching the briefing back to `deliverAs: "followUp"` so it "waits politely" instead of cutting into the orchestrator's tool calls.** That reads as courtesy and is actually the dropped-wake bug: the follow-up queue is only polled after the inner tool-call loop exits, so the briefing is unreachable until the turn ends on its own. Politeness here means a finished subagent the orchestrator never sees.
- **Letting a refusal or a nudge write the `.exit` sidecar "so the parent knows what happened".** The sidecar *is* the done classification; writing one for a run still being asked for its answer hands the parent a success with nothing in it, which is the original bug with extra steps. A refused `subagent_done` performs no side effects at all.
- **Making the answer gate a second predicate, or hardcoding the agent roster it applies to.** There is one `qualifiesAsAnswer` in `rundir.ts` and both halves call it — **and one `visibleTextOf` beside it**, because *what text is judged* is as much of the contract as the rule. Both were briefly duplicated in `child-done.ts`, and the copies had already diverged on string `content` before they were merged: the child could pass its gate on a message the parent read as unanswered. `lib.test.ts` pins them to the same function identity.
- **Tightening parent-side salvage to match the gate.** Measured: it discards two of the three real stranded reports. The gate and the salvage answer different questions at different times; see the convention above before "unifying" them.
- **Adding `additionalProperties: false` to `subagent_done`'s schema to reject a fabricated `message` argument.** Tempting, and it moves the failure earlier — but a schema rejection is retried by the model with no useful guidance and no bound, whereas the gate explains the mistake and gives up after two. The permissive schema is also what makes the parent's argument salvage possible for runs already on disk.
